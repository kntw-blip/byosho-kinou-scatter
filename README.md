# 病床機能報告 散布図分析ツール

厚生労働省「令和6年度病床機能報告」の公表データを病院単位に集計し、任意の2項目の関係を散布図で確認できるツールです。

**公開ページ: https://kntw-blip.github.io/byosho-kinou-scatter/**

## できること

- 病院単位(1点=1病院)と病棟単位(1点=1病棟)を切り替えて表示
- X軸・Y軸を自由に選択(病床数、職種別の常勤換算職員数、診療実績、医療機器、手術・リハビリなど様式2の主要27項目)
- 初期表示は「許可病床数 × 全職種の常勤換算職員数(常勤+非常勤)」
- 主機能(高度急性期・急性期・回復期・慢性期)で色と形を分けて表示、クリックで表示切替
- 都道府県・二次医療圏での絞り込み、病院名での強調表示
- 100床あたり換算、対数目盛、相関係数と回帰直線
- 表示中の病院の一覧表示と CSV 保存
- 表示条件は URL に保存されるため、そのまま共有できます

## データ

| 項目 | 内容 |
|---|---|
| 出典 | [令和6年度病床機能報告 公表データ](https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/open_data_00018.html)(施設票、様式1病棟票、様式2病棟票 年間合計) |
| 対象 | 一般病床・療養病床を有する病院 6,926 施設、27,723 病棟(有床診療所は対象外) |
| 時点 | 2024年7月1日時点。診療実績は2023年4月〜2024年3月 |

主な加工内容:

- **職員数** = 施設全体の常勤(実人数)+ 非常勤(常勤換算)
- **病床数** = 病棟票の許可病床数(一般+療養)の病院合計。機能別は各病棟が選択した機能区分で集計
- **主機能** = 4機能のうち許可病床数が最も多い機能(同数なら急性度の高い方)
- **病床稼働率** = 在棟患者延べ数 ÷(許可病床数 × 366日)、**平均在棟日数** = 在棟患者延べ数 ÷((新規入棟 + 退棟)÷ 2)
- 公表データで「*」(1〜9件の秘匿)となっている値は欠損扱い
- **様式2(手術・リハビリ等の年間件数)** は病棟ごとの値を病院単位に合計。月別のいずれかが1〜9件の病棟は年間値も秘匿されるため、合計は**実際より少ない下限値**です。件数の少ない手技(PCI、放射線治療など)ほど影響が大きくなります。超急性期脳卒中加算と脳血管内手術はほぼ全病棟が秘匿のため対象外としました
- **病棟単位** の職員数は病棟配置の11職種(医師の項目なし)。様式2は様式1と病棟コードの付番が異なるため病棟単位には含めていません
- 1職種の常勤換算が5,000人を超える報告は入力誤りの疑いとして印を付け、画面の初期設定で除外(値自体は変更していません)

病床数には精神病床などを含まない一方、職員数は施設全体の値である点にご注意ください。

## 構成

```
index.html                  画面本体(単一ファイル)
vendor/plotly-gl2d.min.js   描画ライブラリ(Plotly.js, MIT License)
data/hospitals.json         病院単位の集計データ(自動生成)
data/wards.json             病棟単位のデータ(自動生成)
data/build_report.json      集計時の件数・合計などの確認用レポート(自動生成)
scripts/build_data.py       集計スクリプト
.github/workflows/build-data.yml  厚生労働省サイトから取得して集計する GitHub Actions
```

データの再生成は、GitHub の Actions タブで `build-data` を手動実行します。年度を更新する場合は、ワークフロー内のファイル番号と `scripts/build_data.py` の項目名を新年度の公表データに合わせて変更してください。

## 注意事項

本ツールは公表データを独自に加工したものであり、厚生労働省が作成・保証するものではありません。報告値には医療機関の入力誤りが含まれる場合があります。経営判断に用いる際は元データもあわせてご確認ください。
